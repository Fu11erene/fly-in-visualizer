# Fly-in Visualizer 設計

## 目的

Fly-in（`/Users/fu/dev/Fly-in`）の評価の場で、自分のプログラムのターミナル出力が
正しいことをレビュアーに目で見せる。出力をファイルに保存したものとマップファイルを
読み込み、各ターンのドローンの動きを動画プレーヤーのように再生する。

成功の姿: レビュアーが再生を眺め、好きなターンに飛び、「赤がどこにもない＝
ルール違反がない」ことをその場で確認できる。

## ゴール

- 出力ファイルとマップファイルから、全ターンのドローンの位置を復元して描画する。
- 動画プレーヤー風に操作できる: 再生/停止、1 ターン戻る/進む、最初/最後へ、
  倍速（0.5x / 1x / 2x / 4x）、シークバーのクリック・ドラッグで任意のターンへ。
- 操作はマウス（ボタン）とキーボードの両方でできる。
- ターン間はドローンがリンク上をなめらかに移動するアニメーション。
- そのターンに使われているリンクを、目立つ色（オレンジ系）の太線で強調する。
- ゾーンとリンクに「使用数 / 上限」を常時表示する。
- 規則違反を赤で示す（下記「検証」）。
- 画面下に、操作ボタン・現在のターンの出力 1 行（色付き）・キー操作の説明を出す。

## 非ゴール

- 経路の計算はしない。出力を再生・検証するだけ。
- Fly-in 本体のコードは変更しない。import もしない（独立したプロジェクト）。
- 他人の出力形式への対応、出力ファイルの編集機能、動画ファイルへの書き出し。

## アンチゴール（動いても失敗とみなすもの）

- 正しい出力なのに赤が出る（誤検出）。評価の場で自分の出力を疑わせてしまう。
- 違反があるのに赤が出ない（見逃し）。
- 数え方が Fly-in の `ReservationTable` と食い違う。

## 起動方法

```
uv run python main.py <map_file> <output_file>
```

出力ファイルは `python main.py map.txt > out.txt` で作ったもの（ANSI の色コード入り）。
Makefile に `make run MAP=... OUT=...` も用意する。

## 入力形式

### マップファイル

Fly-in と同じ形式（`nb_drones:`、`start_hub:` / `hub:` / `end_hub:` の
`<name> <x> <y> [zone=... color=... max_drones=...]`、
`connection: <a>-<b> [max_link_capacity=...]`、`#` コメント、空行）。

Fly-in で検証済みのマップを読む前提なので、パーサは Fly-in ほど厳密でなくてよい。
ただし読めない行があればエラーメッセージ（行番号付き）を出して終了する。
既定値: `zone=normal`、`max_drones=1`、`max_link_capacity=1`。
start と end の上限は `nb_drones`（`max_drones` の指定は無視）。

### 出力ファイル

- 1 行が 1 ターン。1 行目がターン 1。空行は「誰も動かなかったターン」。
- 各行は空白区切りの移動 `D<ID>-<name>`。
  - `<name>` がゾーン名なら、そのターンの終わりにそのゾーンにいる。
  - `<name>` が `<a>-<b>`（マップに書かれた順の接続名）なら、restricted ゾーンへ
    向かってその接続の上にいる。ゾーン名は `-` を含まないので、`-` で分割すれば
    区別できる。
- 行に現れないドローンは、そのターン動いていない（待機中、または到着済み）。
- 名前の前後に ANSI の色コード（`\033[...m`）が付いている。読み込み時に取り除く。
- 末尾の改行の有無は問わない。

書式として読めない行（`D<数字>-` で始まらない語など）があれば、行番号付きの
エラーを出して終了する。名前やドローン番号の内容の誤りは書式エラーではなく、
下記の「検証」で赤表示する。

## 状態の復元と数え方（Fly-in の ReservationTable と同じ規則）

ターン 0 では全ドローンが start にいる。ターン t の位置は、行 t に現れたドローンは
その位置、現れないドローンはターン t-1 と同じ位置。

ターン t の使用数:

- **ゾーン**: ターン t の終わりにそのゾーンにいるドローンの数（待機中も含む）。
  接続の上にいるドローンはどのゾーンにも数えない。
- **リンク**: ターン t にそのリンクを使ったドローンの数。向きは区別せず合計する。
  - 通常の移動（ゾーン → 別のゾーン）はそのターンにリンクを使う。
  - restricted への進入（ゾーン → 接続の上）は、進入したターンだけリンクを使う。
  - 着陸（接続の上 → ゾーン）と待機はリンクを使わない。
- 上限: ゾーンは `max_drones`（start / end は `nb_drones`）、リンクは
  `max_link_capacity`。

## 検証（赤表示）

次の違反を、ターンごとに検出する。

1. ゾーンの使用数が上限を超えた。
2. リンクの使用数が上限を超えた。
3. 接続のない 2 ゾーン間を移動した（接続の上にいる場合は、その接続が現在のゾーンに
   つながっていない）。
4. blocked ゾーンに入った。
5. restricted ゾーンに、接続の上を経由せずに 1 ターンで入った。
6. 接続の上にいるドローンが、次のターンにその接続の restricted 側へ着陸していない
   （待機した、別の場所へ動いた、など）。
7. 接続の上の行き先が restricted ゾーンではない。
8. 存在しないゾーン名・接続名、または 1〜`nb_drones` 以外のドローン番号。
9. 同じ行に同じドローンが 2 回現れた。
10. end に着いたドローンが、その後また動いた。
11. 最終ターンの時点で end にいないドローンがいる（最終ターンの違反として扱う）。

違反 8・9 のように位置を決められない移動は、そのドローンは前のターンの位置に
留まったものとして以降を続ける（再生は止めない）。

**［私の判断］** 違反があっても位置の復元は止めない:

- 違反 3〜7 の移動でも、行に書かれた位置をそのまま採用する（赤表示はする）。
- 違反 6 で行に現れなかった場合、ドローンは接続の上に留まったものとして描く。
- 違反 9 では、その行の 1 回目を採用する。
- 出力ファイル末尾の空行はターンに数えない（Fly-in の出力は空行で終わらない）。

表示:

- 違反したゾーン・リンクは、そのターンのあいだ円・線・数字を赤で描く。
- シークバーの、違反のあるターンの位置に赤い目印を付ける。
- 現在のターンに違反があれば、出力 1 行の下に理由を短く並べる
  （例: `junction: 3/2 (over max_drones)`、`D3: no connection path_a-goal`）。
- 違反が 1 件もなければ、画面に `No violations` と表示する。

## 画面

ブレインストーミング中にブラウザで見せたモックアップ（A 案 + 操作バー + 強調・
使用数表示）の配置に従う。

- **上（大部分）: マップ**
  - ゾーンは円。マップの座標を、ウィンドウに収まるよう拡大縮小して配置する。
    円の色はゾーンの `color`（Fly-in の `output.py` の `Color` と同じ RGB 表。
    色指定なし・未知の色は灰色）。
  - ゾーン名と「使用数/上限」を円の近くに表示する。
  - リンクは線。中央に「使用数/上限」。そのターンに使われたリンクはオレンジ系の太線。
  - ドローンは番号入りの白い丸。同じゾーンに複数いるときは重ならないよう円周上に
    ずらす。接続の上にいるドローンは線の中点に描く。
- **下: 操作パネル**
  1. シークバー（現在ターン / 最終ターン の表示、違反ターンの赤い目印、
     クリック・ドラッグでジャンプ）。
  2. ボタン: ⏮ 最初へ、◀ 1 ターン戻る、▶/⏸ 再生/停止、▶ 1 ターン進む、⏭ 最後へ、
     速度 0.5x / 1x / 2x / 4x（選択中を強調）。
  3. 現在のターンの出力 1 行。元の色コードどおりの色で表示する（読み込んだ行を
     保持しておく）。ターン 0 では空。
  4. 違反の理由（あれば）。
  5. キー操作の説明: `SPACE play/pause | LEFT/RIGHT step | HOME/END first/last |
     1-4 speed | click bar to seek | Q/ESC quit`。

### 再生とアニメーション

- 1x で 1 ターン 1 秒。倍速はこれを割る。
- ターン t-1 → t の間、ドローンは位置を直線補間して動く。
  restricted への進入は ゾーン → 線の中点、着陸は 線の中点 → ゾーン。
- 移動中の強調・使用数・赤表示は、移動先のターン t のものを出す。
- 1 ターン戻る/進む・ジャンプは、アニメーションせずにそのターンの静止状態へ切り替える。
- 最終ターンに着いたら自動で停止する。停止中に再生を押すと、最終ターンなら最初から。

## 技術的な制約と選択

- Python 3.14、uv、pygame（ウィンドウ・描画・入力）。
  **［私の判断］** マウスのボタン操作となめらかなアニメーションの両方に向くため。
- 開発ツールは Fly-in に揃える: pytest、flake8（79 桁）、mypy
  （`--disallow-untyped-defs` など Fly-in の Makefile と同じオプション）、ruff、
  pre-commit、Makefile（install / run / lint / test / format / clean）。
- docstring は Fly-in と同じ Google スタイル・英語。
- 画面の文言・違反メッセージ・エラーメッセージはすべて英語（ASCII のみ）。
- 読み込み・状態の復元・検証は pygame に依存しない純粋なモジュールにし、pytest で
  テストする。描画と入力は手で確認する。
- テストの `pytest.param` の id はケース番号だけ（例: `V3`、枝番は `V3a`）。

## 実装者に任せること

- モジュール分割、クラス設計、ファイル名。
- ウィンドウの初期サイズ（リサイズ対応の有無を含む）、フォント、細かな色味、余白。
- 座標の y 軸の向き（マップ同士で見やすいほう）。
- マップパーサの厳密さ（上記の最低限を満たす範囲で）。
- 違反理由の文言。
- 実装の手順書（チェックボックス付き。1 手順を終えるごとに ✓ を付ける）。
